# 专注星球 MVP 0.7.5 技术方案

## 0.7.5 后台保存与局部更新

运行期间以 SerialWorkQueue 串行执行同步 SQLite 操作：专注、统计与应用用量共享一个队列，星球成长和布局使用独立队列；Token 导入与读取另行协调。每个队列最多等待 256 项任务，满载拒绝新任务并反馈失败，已接受的任务在关闭时排空。启动时的目录互斥、版本在线备份、数据库初始化顺序保持不变，初次场景与存档初始化仍在启动路径执行。

每秒专注增量捕获实际采样时刻，随后异步落库；不把排队时间补算成专注、不重试不确定的增量。单轮保存失败标记阻止后续累计，界面及时解除限制；结束状态排在先前进度之后保存。系统锁定、注销和休眠递增启动中断代号，设置保存或建会话期间发生过系统中断时，即使随后解锁也取消开始；已创建的会话按零秒中断处理。

关闭会停止计时器，并等待专注保存、CSV 导出、应用用量、Token 任务和已接受的布局修改。若应用用量等保存失败，保留窗口及待保存批次，禁止再次开始专注，允许修复后重试关闭；不会在部分组件已释放后继续计时。CSV 在目标目录中写临时文件后再替换目标，保留原有公式注入防护。

统计直接在 SQLite 聚合并只读取界面需要的最近 12 条记录，按数据修订号、日期与年份合并查询。同年专注热力图复用格子，应用列表按进程名复用行，隐藏页和最小化时延后界面更新。Token 数据只从后台快照读取，立体日历延至首次显示创建。星球首次读完整日汇总，之后只取日期边界以来的专注记录；无新增输入时只读快照，不重复写成长高水位。

场景分为自然地形、可布置物件、选区、天气和生态动画等部分。选择地块只替换标记；放置、移动、旋转或收起物件只更新变化实例，其余冻结网格保持复用。生境变化时重算互动目标，编辑状态切换不重建自然地形。首次初始化通过一次 ApplyState 构建；保留近景、模型精度、120 毫秒动画周期及隐藏暂停机制。这些措施减少主线程工作，不代表已测得硬件 GPU 帧率。

发布门禁扩展为十五组，保留原十组并增加 Usage、Calendar、Codex、Appearance 和 Bridge。测试宿主使用独立 Application 加载资源，避免触发实际 App.OnStartup；数据目录和 Token 来源均为合成目录。专注数据库 schema 保持 1，不重放历史时间。

## 0.7.4 回调延迟恢复

FocusClock 对超过五秒的单次间隔仍不入账并标记 GapDetected；新增 ContinueAfterGap 供调用方显式恢复，保留先前整数秒与小数余量。Advance 不会自行消除标记，原“未确认间隔不计时”边界保留。MainWindow 在回调延迟时显式恢复，不调用 Finish，因此不会误关沉浸窗口、清除严格状态或提前解除限制。真实电源/会话事件和专注记录写入异常仍使用原中断路径。

Tick 先执行 AdvanceFocus，保存进度后才刷新附属统计与星球。PlanetGrowthStore 同时设置 SQLite DefaultTimeout=1 和 busy_timeout=1000；数据库占用时本次成长更新失败并由界面显示原有状态，后续按累计专注观测重试。事务和高水位去重规则保留，未缩短专注数据库的写入等待，也未迁移存档。

## 0.7.3 严格专注

FocusSettings 增加默认 false 的 StrictFocus 字段，保存在已有 settings JSON 中，旧 JSON 缺失该字段时继续普通模式，不迁移数据库或改变历史会话。开始严格专注前显示明确时长与边界的确认框，默认选择取消；确认后才创建会话和启用限制。本轮使用独立的严格状态快照，不从可变设置中反复判断是否允许退出。

紧急按钮、全局热键消息、沉浸 Esc 以及主窗口/沉浸窗口关闭均经过本轮退出判断。普通模式保留原紧急退出行为；严格模式拒绝提前退出，设置面板在计时期间禁用。到期完成、ReleaseForError、系统锁定/注销/休眠的中断路径仍可释放限制并清除本轮严格状态；休息不进入严格状态。未添加操作系统级封锁、驱动、后台重启或禁用任务管理器的行为。

## 0.7.2 单文件发布与资源导出

Windows x64 发布采用自包含单文件：`PublishSingleFile=true`、`IncludeNativeLibrariesForSelfExtract=true`、`EnableCompressionInSingleFile=true`，并设置 `DebugType=none`、`DebugSymbols=false`、`PublishTrimmed=false`。WPF 不裁剪。用户只需复制 `专注星球.exe`；.NET 托管运行时、SQLite 等原生依赖和应用资源随 EXE 发布，不要求目标电脑预先安装 .NET。首次运行该版本时，由 .NET 单文件机制将需要的原生库提取到临时缓存；这不会改变正常数据目录或重新计算已保存秒数。

新的星球图标通过 `ApplicationIcon` 嵌入 EXE，WPF 使用同套图形资源。图标与扩展不从 EXE 旁边的文件夹读取。发布包可另附文档和备用扩展，但程序启动不依赖这些附带文件；不新增安装器或注册表配置。

`PackagedAssets.EnsureBrowserExtension(dataDirectory)` 接受显式绝对数据目录，返回其下固定的 `browser-extension` 路径。主窗口在用户点击“打开扩展文件夹”时调用它。资源名统一为 `FocusGarden.BrowserExtension.<文件名>`，包含 `background.js`、`controller.js`、`manifest.json`、`popup.css`、`popup.html`、`popup.js`、`rules.js`、`README.md` 共 8 个文件。

导出先将全部资源读入内存，再检查目标目录的所有祖先及现有目标文件，拒绝符号链接、目录联接和文件/目录占位冲突。相同字节不重写；不同文件先写入同目录的随机临时文件并落盘，再以 `File.Replace` 或同目录 `File.Move` 提交。替换以单个文件为单位，8 个文件不是整体事务；失败时报告错误，重试可补全尚未完成的文件。不会覆盖非包内文件，也不读取或修改专注库、备份或配对密钥。

固定导出路径让浏览器已加载的位置不随 EXE 移动或更新而变化。更新后用户需再次点击导出按钮，并在 Edge/Chrome 中重新加载扩展；首次加载和配对仍为手动步骤。导出目录不是浏览器自动安装接口，也不扩大原有网站限制范围。

`build.ps1` 要求新的或空的 `Destination`，通过 `WorkDirectory` 将中间产物放到独立工作目录。发布后先确认输出只有主 EXE，再复制文档和备用扩展；不会删除非空输出目录中的旧文件。使用示例：

```powershell
.\build.ps1 -Destination .\outputs\FocusPlanet-0.7.4 -WorkDirectory .\work\build
```

## 0.7.1 模型精修

在原生 WPF 3D 中细化生物形体和植物轮廓，主要曲面复用冻结球面网格，微小细节使用低面数几何。山体使用缓存的多层山脊和不规则雪线；眼睛与池塘水面使用少量缓存的高光材质，其余场景保持漫反射。没有新增游戏引擎、贴图下载或包依赖。几何上限仍为测试中的 220,000 个实例三角形，最终实测见本版验收报告。

保留既有 120 毫秒共享动画计时器、背面/视口外跳过、窗口隐藏暂停机制，不增加逐帧建模或存档写入。存储格式、固定地块、成长公式和互动规划保持原样。

## 更新与专注记录不变约束

正常路径由 `FocusDataProtection.DefaultDataDirectory` 固定为 `%LOCALAPPDATA%\FocusGarden`。在构造任何存储与执行中断恢复之前，App 获取实例锁和物理数据目录锁，再按程序集版本执行 `PrepareForVersion`。Windows 路径身份使用目录句柄解析，避免 junction 等目录别名产生两个互斥名；测试/验收要求独立的显式目录，并拒绝默认目录及其别名。

源库只读事务固定一致快照，`BackupDatabase` 纳入 WAL 中已提交数据；临时备份执行完整性检查与专注表逐行指纹比对，转为 DELETE 日志模式、关闭并独立重开复查。成功后原子改名并更新版本标记；任何一步失败都不会进入原库的初始化/恢复流程。此备份覆盖 `focus.db` 内的专注、按日记录、设置和应用时长，不是所有星球/Token 数据的整套备份。

FocusStore 在修改日志设置前检查 schema 版本，拒绝不支持的较新版本。新表创建及版本写入在同一事务内，已有 v1 不改版本；中断恢复仅修改状态和结束时间，不改变已保存秒数，不补算离线时间。每次发布以旧版原始 schema fixture 检查逐条会话/逐日秒数、跨日跨年、反复升级、WAL、失败保留与独立备份。

专注星球将实际专注时间与本机 Codex Token 用量转换为小星球的成长。开局是荒凉星球，随后出现植被、生物与可布置的建筑；每颗星球满六个自然月后可开拓下一颗，已有家园继续保留。0.3 的番茄钟、背景图片、当前时间、年度专注热力图、应用时长、Token 立体日历、统计导出和使用限制继续可用。

## 成长规则与六个月周期

每天按本地自然日，使用启用星球后新增的有效专注秒数 S 和新增 Token 数 N：

```text
专注点 F = min(120, floor(S / 60))
Token 点 T = min(60, floor(15 × log₂(1 + N / 100000)))
共同助力 B = min(20, floor(min(F / 3, T)))
每日成长 G = F + T + B，最多 200 点
```

两项来源均可独立贡献成长；同时使用时获得共同助力。Token 点递减并封顶：10 万 Token 为 15 点，30 万为 30 点，150 万达到 60 点上限。它只是养成权重，不表示学习质量、工作成果或费用。休息不计专注，提前结束和中断已保存的实际时间仍有效，不扣已有成长。

| 等级 | 阶段 | 累计成长门槛 | 最低星龄 | 景观与解锁 |
| --- | --- | ---: | --- | --- |
| 0 | 初生星球 | 0 | 启用时 | 荒凉地表、海洋和山石；岩石庭园可布置 |
| 1 | 森林萌芽 | 150 | 无额外月份要求 | 植被；树木、花丛、池塘、草地、蘑菇丛、果树、灌木可布置 |
| 2 | 生命栖息 | 1,200 | 1 个自然月 | 自然生物出现，六种生物可手动布置 |
| 3 | 定居家园 | 3,000 | 2 个自然月 | 小屋可布置 |
| 4 | 风能文明 | 5,500 | 3 个自然月 | 风车、观测塔可布置 |
| 5 | 星际绿洲 | 9,000 | 5 个自然月 | 天文台可布置，夜间可能出现极光 |

阶段同时要求成长值和星龄。月份按该星球 `ActivatedAt.AddMonths(n)` 判定，保留启用时刻，月末按日历规则处理；六个自然月不是固定 180 天。满六个月即可开拓新星球，无需达到最高等级或刷满成长值；不会自动清空旧星球，也可继续建设。每颗星球只能开拓一次后继星球。

`PlanetGrowthStore` 保存多颗星球的名称、启用时刻、随机种子、当前选择与成长分配。新星球从 0 点开始，旧星球与其布局保留；选择旧星球后，后续成长可继续分配给它。切换和开拓前先结算已有记录，专注、休息或用量导入进行中不执行切换。

### 防重复与记账边界

- 首次启用保存当日已有专注秒数作为基线，旧日期和基线以前的专注不兑换成长。历史仍保留在原统计中。
- 首次绑定 Token 来源以全局星球启用时刻为截止；更换来源或切回旧来源，以切换时刻开始新观察期。同一天内的筛选由导入器按事件时间完成。
- 每日专注和当前来源观察期内的 Token 汇总保存最高已见值。重复刷新、缺失、数值下降及恢复均不重复奖励，也不扣除已奖励成长。
- 各来源观察期的新增 Token 合并为每日永久累计。每日目标成长只奖励正差额，高水位、每日奖励和星球份额在同一事务中更新。
- 防重复状态和每日 200 点上限由所有星球共享；切换不重算旧记录。新增成长只分给当前星球。“今日共”是全局每日值，“本星球”是当前星球所得份额。

数据库保证正常操作中的记账一致性，不提供服务器时间验证或防篡改服务；系统时间和本机日志是本地信任输入。

## 三维星球与布局

星球采用 WPF `Viewport3D`、实际三维网格、光照和透视相机。左键拖动旋转，滚轮缩放，双击或“重置视角”复位。专注期间缓慢转动，云和动物使用轻量动画；布局模式暂停相关动画，便于选中物体。

每颗星球有 **32 个固定地块**，每块最多一个可编辑物品。编辑采用点击地块吸附：选择类型后放置，选中已有物品后可移动到空地块、按 90° 旋转或收起。每次成功操作立即写入 `planet-layout.db`，按稳定的 `PlanetId` 隔离。解锁后布置不消耗成长值，收起后可重新放置。

目录共 18 种：原 6 种的标识、顺序、解锁等级和数量上限不变，追加 6 种生物与 6 种景观。`PlanetBuildingDefinition` 保持原四参数调用兼容，并提供可选 `Category`、`Hint`。界面按建筑、景观、生物排序显示，仍以 `Kind` 绑定实际类型。`IsAnimal` 对自然场景的非目录标识或未知值返回 false。

`Place` 使用即时写事务，在同一次事务中校验地块占用、单种数量和每星球手动生物合计 12 只上限，避免并发连接同时通过检查。自然生物单独最多 12 只，所以自然与手动生物合计最多 24 只；云等非生物不计入该数量。

这是固定地块布局，不是任意坐标拖放、地形雕刻、道路绘制或完整沙盒建造。自动生成的山石、植被、自然生物和天气不属于可编辑地块内容；手动生物拥有稳定布局记录。生物使用自动的简单互动，没有繁殖、食物资源或生存模拟。

### 真实邻近景观与编辑归位

场景构建时收集实际存在的自然景观和手动景观，按物种偏好寻找附近匹配目标。选择依据是球面法向量之间的角距离，搜索范围约 0.68 弧度；地面生物还对短弧上的中间点采样，避免明显跨海。蝴蝶不受地面路径检查限制。该算法没有完整寻路或碰撞系统，不保证任意复杂布局都能通行。

兔子选择草地、花丛或灌木；绵羊选择草地、果树或树木；狐狸选择灌木、树木或蘑菇丛；鸭子选择池塘；鹿选择池塘、树木或果树；蝴蝶选择花丛、果树或蘑菇丛。目标从真实景物位置解析，不是给动物播放与场景无关的固定动画。没有可达目标时保留原地活动。

每个生物保存运行期间的 Home、Destination、Habitat 等场景状态，观察时在原位置与目标附近做短距离活动。布局数据库只保存原地块与朝向，不保存每一帧位置。进入编辑模式后，生物回到原地块并暂停活动，原有命中、移动、旋转和收起继续围绕稳定布局记录执行；退出编辑后恢复活动。

### 动画工作量控制

整个星球视图共用一个约 120 毫秒间隔的 `DispatcherTimer`；各生物没有独立计时器。动画更新变换，场景原型和冻结几何使用缓存，只有实际场景状态或布局变化时才需要重建相关场景。

页面不可见、场景离开可视区、窗口最小化、拖动或编辑期间停止场景动画；重新可见后恢复。该控制只作用于三维画面，不暂停专注计时或改变已保存记录。计时器间隔不是测得的渲染帧率，不能据此承诺所有设备都流畅；0.7 的实际性能以本次发布验收为准。

### 布局 schema 0 → 1

旧 `planet-layout.db` 的 `user_version=0`，类型 CHECK 仅包含原六种。0.7 将布局版本提升到 1，并允许目录中的全部 18 种；该版本号与 `focus.db` 的 schema 各自独立。

存在旧布局时，迁移前用 SQLite 在线备份固定一致快照，包含已提交的 WAL 页面。备份写入同目录 `backups/planet-layout-before-v1-<时间>-<唯一编号>.db`，比较全部布局行的指纹，并在转成 DELETE 日志模式、关闭和只读重开后复查。新库直接建立 schema 1，内存测试库不创建磁盘备份。

迁移开始时取得即时事务，再确认原布局与备份快照一致；建立新表、复制全部行并比较星球 ID、物品 ID、类型、地块和朝向，然后替换表并更新版本。任何异常回滚整个事务，已完成备份保留。未知较新版本拒绝打开；已有 schema 1 不重复迁移。布局存储明确拒绝打开名为 `focus.db` 的文件，不在迁移中更改专注库。

天气由星球种子和本地三小时时段确定，同一时段刷新不会重新抽取；晴朗、多云、轻雨均可出现，最高阶段夜间可能有极光。夜间为本地 19:00 至次日 06:00。天气不连接真实天气服务，也不因休息或中断惩罚星球。

## 专注、应用时长与统计

专注使用 `Stopwatch` 与 `FocusClock` 累计实际有效秒数，不用系统时钟倒推已完成时长。达到计划时长才标记完成；紧急退出和中断保留已保存秒数。系统休眠、锁屏、注销会中断本轮；超过五秒的回调间隙只跳过不确定时间并继续，停顿不补计。重启恢复遗留会话时只保留最后检查点，不把停机时间算作专注。

`focus.db` 中的会话与按日累计在同一事务更新，跨午夜、跨年按当时本地日期分配。年度热力图包含所有状态的实际秒数，完成番茄数只取完成记录；休息不计入。最近记录显示 12 条，CSV 最多导出最近 100,000 条，采用 UTF-8 BOM 并防止任务文本触发表格公式。

自选背景复制到数据目录，原图不修改；主页和全屏页使用暗色蒙层保持文字可读，并显示当前日期时间。当前时钟与专注计时使用不同时间源。

应用时长每约 250 毫秒采样前台进程，只有前后为同一应用、未锁定、两端空闲均少于 60 秒且间隔少于三秒时才累计。每约五秒保存，按本地日期分配。只保存进程名、日期和秒数，不保存窗口标题、网址或输入内容；不补算启动前、后台、休眠或未知间隔。这是前台活跃使用的近似统计。

## Token 日志与立体日历

`CodexUsageImporter` 只读扫描所选 Codex 根目录内 `sessions` 和 `archived_sessions` JSONL，提取 `event_msg/token_count` 用量记录。默认沿用保存的目录，否则使用 `CODEX_HOME` 或用户目录下 `.codex`。历史日志格式可能变化，不能视作长期稳定的账单接口。

缓存独立保存到 `codex-usage.db`，仅索引用量元数据，不保存或展示会话正文。副本、归档和重复累计按事件信息去重；缺失历史只使用有证据的增量，不凭空补算。缓存输入已包含在输入中，推理输出已包含在输出中，不能再次相加。不同来源查询隔离，导入失败时不把旧来源冒充新来源。

Token 日历仍为十二个月、4×3 排列的三维柱图，支持旋转、缩放、悬停数值与平方根/线性柱高。灰格表示无可读取记录，不代表账号实际使用为零。程序可手动刷新或运行期间每两分钟刷新；关闭后不继续读取。

**Token 数据是本机日志估算，不是官方费用账单、余额或账号限额百分比。**其他设备、云端、删除的记录、未落盘事件或不支持的格式可能不被覆盖。年度日历可展示历史，而星球只奖励符合启用时间及来源观察期的新记录，因此二者数字可以不同。

## 限制与紧急退出

应用限制按进程名精确匹配前台窗口并请求最小化，不强制结束进程。系统桌面、任务管理器、程序自身和部分恢复工具受保护；管理员窗口、改名程序和特殊窗口可能绕过，后台任务不受控制。

浏览器扩展通过 `http://127.0.0.1:17839/state` 只读获取状态，使用本机随机配对码。MV3 临时规则只阻止目标域名及子域的新主页面导航，不读取网页正文；已加载页面、现有媒体流、部分单页应用和未启用扩展的浏览器不受覆盖。通常约五秒同步，并有定时唤醒和约十五秒租约；浏览器挂起时清理脚本也会暂停，不能承诺固定解除时限。

普通模式下，`Ctrl + Alt + Esc` 注册成功时立即结束本轮；主窗口和全屏保留紧急退出按钮，全屏 Esc 和关闭操作进入确认。快捷键注册失败会提示改用按钮。严格模式禁用上述应用内入口，到期或系统/异常中断时释放；严格判断使用本轮快照。网站限制可通过“解除限制并取消配对”或禁用扩展恢复。

全屏是单个显示器上的普通置顶窗口，不是 Windows 安全桌面或系统锁屏；不承诺阻止系统快捷键或绝对无法退出。不安装内核驱动，不修改 hosts、DNS 或防火墙规则。

## 0.5 渲染补充

地表为单个 5,120 三角形平滑球面，采用每等级缓存的 1024×512 程序生成经纬贴图。UV 经度接缝展开、左右像素一致、极点采样位于首末行中心。小景观共享冻结圆体/盒体网格，材质按颜色缓存。0.5 历史记录中的成熟晴天自然场景约 12.1 万三角形、暖缓存单次构建约 15 ms，仅属于当时版本的本机观测，不作为 0.7 性能或所有设备帧率的结论。

展开窗口重用原场景控件和原布局工具栏，关闭后归还父容器，不创建第二份存档。主视图、展开观景与展开布置均继续使用原来的可见性和编辑状态控制动画。

## 0.6 地表近景

同一 `Viewport3D` 在全星球与地表近景两种相机配置间切换，不重建场景或复制地表图片。近景相机沿固定球外径向调整距离，根据球体角半径与视口纵横比计算真实上方切线，使中央地平线位于视口约 56% 高度；地表超出画框下沿，星空继续使用原背景。

逻辑经纬观察角与具体渲染变换分离，近景添加固定俯仰偏移，将当前区域带到近处地表。两个模式独立保存本次运行内的缩放，缩放范围受限以防相机进入球体。切换和缩放只改相机及变换，不改变成长等级、地块编号或建筑列表。

近景输入灵敏度降低，停止整球专注自动转动；动物与云朵动画沿用原变换。原射线命中检测用于近景布置，遮挡规则保持一致。新模式不写入数据库，关闭程序后恢复默认全星球视角。

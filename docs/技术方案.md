# 专注花园 FocusGarden 0.1 技术方案

## 目标与已确认边界

第一版面向 Windows x64，采用 C#、.NET 8 WPF、SQLite 与 Edge/Chrome Manifest V3 扩展。交付自带运行时的便携程序 `FocusGarden.exe`、浏览器扩展和可编辑源码。

用户已确认以下边界：应用限制只阻止前台使用，不强制结束进程；网站限制由浏览器扩展执行；保留紧急退出与系统级恢复途径，不承诺无法绕过的系统锁定。程序不安装内核驱动，不修改 hosts、DNS 或系统防火墙规则。

全屏沉浸采用单个显示器上的普通置顶窗口。它不是 Windows 安全桌面或系统锁屏，也不会将其他显示器一并遮挡。

## 模块

| 模块 | 职责 |
| --- | --- |
| `FocusGarden.App` | WPF 窗口、设置界面、计时协调、全屏、应用限制、系统事件、统计、CSV 与本机桥接服务 |
| `FocusGarden.Timing` | 可独立测试的单调时间累计器 `FocusClock` |
| `FocusGarden.Core` | SQLite 存储、设置与记录模型、域名和进程名校验 |
| `browser-extension` | MV3 后台同步、临时请求阻止规则、配对与解除界面 |

主界面提供“开始专注”“专注统计”“使用限制”三个入口。工作模式中保持正常桌面操作；全屏模式显示任务、倒计时与紧急退出按钮。两种模式使用相同计时、存储和限制状态。

## 计时与会话状态

桌面以约 250 毫秒的调度周期读取 `Stopwatch` 单调时间差，再交给 `FocusClock` 累计。显示和存储使用累计后的整数秒；计数封顶于本轮计划时长，不用“计划结束时刻减当前系统时钟”推算已完成时长。

`FocusClock` 对小数累计采用补偿求和，避免反复累计小间隔导致可见少计一秒。大于 5 秒的单次间隔触发不可恢复的间隙状态，本轮转为中断，不计入该间隙。系统休眠、锁屏与注销事件也触发中断。停顿判定保守，严重界面卡顿可能导致一轮被中断。

| 状态 | 触发与记账 |
| --- | --- |
| `running` | 本轮已开始，逐次写入有效专注秒数 |
| `completed` | 实际累计达到计划时长；才增加完成番茄数 |
| `emergency` | 用户紧急退出；保留实际时长，界面显示“提前结束” |
| `interrupted` | 休眠、系统会话事件、长时间停顿或启动时发现遗留会话 |

休息使用相同倒计时组件，但不创建专注记录、不启用限制。第一版的休息和下一轮专注均由用户手动启动。

持久化恢复不根据启动时刻补算时间：上一进程遗留的 `running` 记录在重启时转为 `interrupted`，结束时刻取最后已成功写入的检查点。异常退出前尚未保存的少量时间可能丢失。

## SQLite 数据模型与统计口径

正常数据目录为 `%LOCALAPPDATA%\FocusGarden`，数据库为 `focus.db`。使用 `Microsoft.Data.Sqlite 8.0.22`；开启外键、WAL 日志、完整同步，并设置繁忙等待。数据库连接内的操作串行化，进度与日期累计使用同一事务。

| 表 | 内容 |
| --- | --- |
| `settings` | 单份 JSON 设置：专注/休息分钟数、默认模式、应用与域名列表 |
| `sessions` | 任务、开始/结束时间、计划/实际秒数、状态、最后检查点 |
| `session_days` | 每个会话在每个本地日期贡献的整数秒数 |

数据库约束保证实际秒数非负且不超过计划时长，并通过部分唯一索引限制为一个进行中会话。结束为 `completed` 时必须已累计足额时长。任务与配置使用参数化 SQL。

`AddProgress` 接收调用者确认的有效时间增量，事务内同时更新会话和按日数据。跨午夜或跨年的区间按运行计算机的本地时区拆分，不将整轮全部放到开始日或结束日。日期累计保存后不会因为以后更换时区而重新归类；小数边界分配最多存在不足一秒的粒度差，整数总量保持一致。

热力图和专注天数累计所有状态的实际秒数；完成番茄数只取 `completed`，按结束时间的本地年份计入。休息不属于任何专注指标。未来日期不生成虚构记录。

界面最近记录显示 12 条；统计查询和 CSV 当前最多读取最近 100,000 条会话。日期累计不受该条数限制。CSV 使用 UTF-8 BOM、标准字段引用，并处理任务文本可能引发的表格公式执行。

## 应用限制

桌面检查前台窗口及其所属进程，将进程名与保存的名单进行不区分大小写的精确比较；命中时请求最小化窗口。不会终止进程、关闭文档或修改应用设置。

系统进程、桌面、任务管理器、番茄钟自身及部分恢复工具被排除。应用名称只接受进程名，不接受路径。前台轮询属于普通用户态辅助，管理员窗口、特殊窗口、可执行文件改名及不同启动方式可能绕过；后台音频和任务不在限制范围。

## 浏览器扩展与本机桥接

桌面监听 `http://127.0.0.1:17839/state`，仅提供只读 GET 状态。扩展使用 `X-Focus-Token` 请求头提交 32 字节随机值编码生成的配对码；桌面将配对码保存在 `browser-pairing.key`，扩展保存在当前浏览器配置文件的本地存储中。接口不能开始、结束或修改专注记录。

状态包含 `active`、`domains`、`leaseExpiresAt` 和 `sessionEndsAt`。桌面在有效专注中持续刷新约 15 秒租约；结束或解除时发布非活动状态。桥接服务自身错误会在界面提示，不妨碍独立的倒计时和应用限制。

扩展采用 `declarativeNetRequest.sessionRules`，规则只匹配目标域名及其子域的主页面新导航。已加载页面、现有媒体流、部分单页应用操作及未安装扩展的浏览器不受此规则覆盖。扩展不读取网页正文，也不上传浏览记录。

同步通常每 5 秒尝试一次，同时注册约 30 秒的浏览器 alarm 唤醒。收到非活动/过期状态、配对或通信失败时清除规则；后台工作进程重启时先清除旧规则，再重新确认状态。扩展限制可接受的未来租约长度，并处理并发旧请求覆盖新状态的问题。

临时规则不会在浏览器完整重启后永久保留。但 DNR 规则本身不具备硬性到期时间；如果浏览器挂起，执行清理的脚本也可能暂停。因此“15 秒租约”“5 秒同步”不等于保证在相同时间内解除。用户可随时点击「解除限制并取消配对」或禁用扩展。

## 紧急退出与错误恢复

主窗口尝试注册 `Ctrl + Alt + Esc` 全局快捷键，成功时立即结束本轮；注册失败则在主界面提示改用按钮。全屏和主界面保留可见紧急退出入口，按钮、全屏 Esc 和关闭请求进入确认流程。结束时先释放桌面限制并发布非活动状态，再完成记录与界面更新。

系统提供的任务管理器等恢复途径仍然有效。第一版不抢占安全桌面、不拦截系统安全快捷键、不安装持久化限制服务。浏览器端恢复遵循上述扩展同步边界。

## 验证与交付边界

已有自动化验证覆盖 SQLite 持久化、设置校验、状态转换、跨日/跨年/闰日、恢复不补算停机与进程保护。计时和扩展各有独立测试，扩展测试采用模拟 Chrome API；模拟测试不能替代真实浏览器的加载、配对、阻止与解除验收。

本文件说明实现与验证方法，不单独证明便携包、不同 Windows 配置、多显示器、高 DPI、真实休眠事件或各浏览器版本均已验收。最终实际执行过的检查与尚未验证项目应以交付时的验证记录为准。

后续可在不改变紧急恢复边界的前提下扩展多显示器遮挡、任务分类、连续轮次、更多统计和更易安装的扩展分发；系统级防绕过不属于当前 MVP 的承诺。

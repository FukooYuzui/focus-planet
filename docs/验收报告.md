# 专注星球 0.6.1 验收报告

## 结果

0.6.1 保留地表近景，新增更新前专注数据库保护。Release 构建和 Windows x64 自包含发布通过，程序集版本 0.6.1。整个验证过程只使用合成数据，不读取或修改用户真实专注存档。

本次自动检查 34 项全部通过：专注核心 12 项、升级保护与目录身份 12 项、主窗口集成 10 项。

## 升级时专注时间不变

升级 fixture 直接使用 v0.1.0 提交 ef4403caf364179b820d015dfbed13f4954a5efd 的原始建表 SQL，覆盖完成、提前结束、中断和遗留运行四种记录，以及跨午夜、跨年和闰日，共 263 秒。不是用当前构造器模拟旧格式。

升级前后逐条比对会话秒数和按日分配，均保持一致；连续多个应用版本、每版重复启动不会重新计入旧时长。恢复遗留运行记录仅改变状态和结束时刻，已保存秒数不变。新增真实计时仍正常累计。

WAL 验证确认未检查点的已提交 17 秒被包含在在线备份。将单个备份复制至独立空目录后，无 WAL/SHM 附属文件仍可读，所有行、时长、integrity_check 和 DELETE 日志模式均符合预期。

## 失败与并发保护

- 备份目录无法写入时，原库不变，不写完成标记。
- 已有备份标记时，新版本备份失败不会把标记错误更新为成功。
- schema 99 被拒绝，不降为 schema 1，不改变已有库内容。
- 损坏数据库不会删除或替换为空库。
- Windows junction 的实际测试证明同一物理目录及不存在尾路径得到同一身份，不同目录不会混淆；符号链接和 8.3 别名未单独实测。
- 验收/测试启动要求独立显式目录；数据目录锁阻止另一个新版实例并行初始化同一份库。

## 发布程序实际启动检查

用旧格式合成记录运行已发布的“专注星球.exe”两次：每次退出码 0，Ready=true、Version=0.6.1。原 88 秒在两次启动后仍为 88 秒，每条会话和每日分配一致。只创建一份升级前备份，备份仍保留恢复之前的原运行状态。

未提供独立目录的验收与测试启动均退出 2。持有相同数据目录锁时，发布程序退出 3，未继续初始化。

## 后续发布约束

build.ps1 在发布前运行专注核心、升级保护和主窗口集成三组检查，任一失败即停止发布。AGENTS.md 固化用户要求：数据位置不随版本变化、不清空/重算/重复累计已保存时长、升级前校验备份、拒绝未知较新 schema、测试使用独立合成库。

正常数据目录固定为 %LOCALAPPDATA%\FocusGarden。备份保存在其中 backups 子目录，仅覆盖 focus.db；星球和 Token 的其他数据库仍应随整个数据目录备份。已有备份不自动删除。

本次验证包括自动检查、已发布程序隐藏初始化与数据库精确比较，未执行整套真人桌面交互或实际浏览器限制验收。0.6 的地表近景源文件与已发布版本保持一致，主窗口展开/返回及成长布局检查仍通过。

# 专注星球 0.7.0 验收报告

## 0.7 本轮已确认的检查

本轮仅使用独立合成数据。通过干净源码目录执行 build.ps1，七组共 **137 项全部通过**：专注核心 12、升级保护 12、布局 25、成长 29、几何 16、星球视图 32、主窗口集成 11。Release 构建无警告/错误，Windows x64 自包含发布成功，版本为 0.7.0。

布局检查覆盖 18 种内容、全部新增种类持久化、类型数量限制、每星球 12 只手动生物上限及并发约束。布局迁移使用冻结的旧版六类型建表 SQL，逐行比较星球、物品 ID、类型、地块及朝向，验证 WAL-only 记录备份、独立备份重开、备份失败保留、未知版本拒绝和迁移中途事务回滚。

主窗口集成包含在 UI 中放置全部 12 种新增内容并验证持久化。原控件名与 Kind 绑定保留。视图检查验证六类生物寻找真实邻近目标、无目标时的回退、编辑归位、几何引用不变、独立物品点击身份、相机外与背面停止动画更新。实际离屏窗口验证最小化/恢复、隐藏页面、滚出/滚回及卸载重挂后的计时器行为；保留全星球与地表近景全部回归检查。

场景使用一个 120 毫秒的动画计时器，手动与自然生物分别最多 12 只，最多另有 3 朵云。相同类型复用冻结网格与材质，每个可选物品保留独立模型包装；动画只更新变换，不生成新网格、不写数据库。自然景观位置缓存最多 4 个种子。

### 本机性能观测

填满 32 地块、遵守每种数量限制的最重组合，在雨天为 186,612 个实例三角形、3,187 个几何模型、303 个唯一网格，低于 220,000 的测试上限。12 只手动生物的雨天满布局为 156,712 个实例三角形，动态对象合计 27 个。

对最大动态布局预热后采样 600 次托管变换更新：总览 P95 约 0.0484 毫秒、近景约 0.0471 毫秒；每次约分配 3.8 KB / 1.2 KB（WPF 属性更新并非零分配）。这是本机的动画变换测量，不包含 GPU 渲染，也不等于整窗帧率或整程序内存占用；不承诺其他设备的固定帧率。

### 已发布程序升级检查

使用真正的 v0.1.0 专注建表 SQL 和 v0.6.1 六类型布局建表 SQL生成独立合成旧库。运行本次已发布的“专注星球.exe”两次，均退出 0、Ready=true、Version=0.7.0。

- 原有专注 88 秒在两次启动后仍为 88 秒，每条会话与每日分配均相同。
- 两颗星球的 12 条旧布局逐行相同，保留物品 ID、类型、地块及朝向；布局版本升级为 1。
- 创建 1 份专注备份、1 份布局备份，二者逐行等于升级之前的原始记录；第二次启动不重复备份。
- 遗留运行会话只从 running 变为 interrupted，已保存的 17 秒不变。
- 未提供独立目录的安装检查与测试模式均退出 2，不读取真实用户数据。

合成近景预览来自实际控件渲染，并验证示例鸭子的互动终点确为画面中的池塘。预览不代表用户的成长或专注记录。本轮未重复整套浏览器限制验收，也未操作用户真实存档。

## 0.6.1 历史验收记录

以下记录属于 0.6.1，用于保留数据保护功能的验证来源；本版本的发布检查以本节之前的结果及发布日志为准。

### 历史结果

0.6.1 保留地表近景，新增更新前专注数据库保护。Release 构建和 Windows x64 自包含发布通过，程序集版本 0.6.1。整个验证过程只使用合成数据，不读取或修改用户真实专注存档。

本次自动检查 34 项全部通过：专注核心 12 项、升级保护与目录身份 12 项、主窗口集成 10 项。

### 升级时专注时间不变

升级 fixture 直接使用 v0.1.0 提交 ef4403caf364179b820d015dfbed13f4954a5efd 的原始建表 SQL，覆盖完成、提前结束、中断和遗留运行四种记录，以及跨午夜、跨年和闰日，共 263 秒。不是用当前构造器模拟旧格式。

升级前后逐条比对会话秒数和按日分配，均保持一致；连续多个应用版本、每版重复启动不会重新计入旧时长。恢复遗留运行记录仅改变状态和结束时刻，已保存秒数不变。新增真实计时仍正常累计。

WAL 验证确认未检查点的已提交 17 秒被包含在在线备份。将单个备份复制至独立空目录后，无 WAL/SHM 附属文件仍可读，所有行、时长、integrity_check 和 DELETE 日志模式均符合预期。

### 失败与并发保护

- 备份目录无法写入时，原库不变，不写完成标记。
- 已有备份标记时，新版本备份失败不会把标记错误更新为成功。
- schema 99 被拒绝，不降为 schema 1，不改变已有库内容。
- 损坏数据库不会删除或替换为空库。
- Windows junction 的实际测试证明同一物理目录及不存在尾路径得到同一身份，不同目录不会混淆；符号链接和 8.3 别名未单独实测。
- 验收/测试启动要求独立显式目录；数据目录锁阻止另一个新版实例并行初始化同一份库。

### 发布程序实际启动检查

用旧格式合成记录运行已发布的“专注星球.exe”两次：每次退出码 0，Ready=true、Version=0.6.1。原 88 秒在两次启动后仍为 88 秒，每条会话和每日分配一致。只创建一份升级前备份，备份仍保留恢复之前的原运行状态。

未提供独立目录的验收与测试启动均退出 2。持有相同数据目录锁时，发布程序退出 3，未继续初始化。

### 当时的发布约束

0.6.1 的 build.ps1 在发布前运行专注核心、升级保护和主窗口集成三组检查，任一失败即停止发布。AGENTS.md 固化用户要求：数据位置不随版本变化、不清空/重算/重复累计已保存时长、升级前校验备份、拒绝未知较新 schema、测试使用独立合成库。0.7 的七组门禁见本报告开头。

正常数据目录固定为 %LOCALAPPDATA%\FocusGarden。备份保存在其中 backups 子目录，仅覆盖 focus.db；星球和 Token 的其他数据库仍应随整个数据目录备份。已有备份不自动删除。

本次验证包括自动检查、已发布程序隐藏初始化与数据库精确比较，未执行整套真人桌面交互或实际浏览器限制验收。0.6 的地表近景源文件与已发布版本保持一致，主窗口展开/返回及成长布局检查仍通过。
